## 개발 PC에서 빌드

프로젝트 루트에서 실행한다. 회사 연결·공개 지도 값은 기존 개발 `.env`에서 검증해 선택한다.
공개 설정 생성기는 비밀 키를 거절하며 환경 파일 원문을 설치본에 복사하지 않는다.
첫 회사의 실제 고객 DB·인증 세션·Mac 선택 DB 위치는 빌드 입력이 아니다.

설치 파일 검사는 NSIS를 읽는 정식 7-Zip 콘솔 도구가 필요하다.
`7zip-bin`의 `7za`만으로는 NSIS 검사까지 완료할 수 없다.
Windows 개발 PC에서는 공식 7-Zip을 설치하고 PowerShell에서 경로를 지정한다.

```powershell
$env:DEMO_7ZIP = "C:\Program Files\7-Zip\7z.exe"
npm ci
npm run desktop:build:win
```

Mac에서는 [7-Zip 공식 다운로드](https://www.7-zip.org/download.html)의 콘솔 도구 경로를 지정한다.
이번 검증에서 사용한 버전은 26.04이며 `artifacts/desktop/tools/7zip-26.04/7zz`에 있다.

```sh
DEMO_7ZIP="$PWD/artifacts/desktop/tools/7zip-26.04/7zz" npm run desktop:build:win
```

`npm run desktop:prepare`는 공개 설정·현장 화면·운영 의존성까지만 준비한다.
두 명령 모두 기존 `mobile/dist`와 APK를 덮어쓰지 않는다.
현장 화면은 PC 공개 설정과 같은 회사·공개 지도 값으로 별도 생성한다.

준비 폴더는 `artifacts/desktop/windows/staging/`이다. 도구가 소유 표식을 남긴 이 폴더만
다음 빌드에서 다시 만들며, 다른 폴더·기존 완성 릴리스는 자동 삭제하거나 덮어쓰지 않는다.
같은 버전의 완성 릴리스가 있으면 빌드가 중단된다. 기능을 변경해 다시 배포할 때는
버전을 올리고 기존 설치본·해시·검증 기록을 유지한다.

## 설치본의 파일과 자료 저장

합의한 운영 방향:

- 확정된 업무자료의 원본은 서버에 둔다.
- PC에는 다시 만들 수 있는 조회 사본과 미완료 요청·초안만 필요한 범위에서 둔다.
- 회사에 개발 환경을 복사하지 않고 설치 프로그램과 정식 APK를 전달한다.
- 설치 파일에는 고객자료·개발용 `.env`·서명 비밀번호·서버 관리자 키를 넣지 않는다.
- 상세 백업 주기·장비 선정, 통합 운영자 화면, 서버 증설 자동화는 첫 단계에서 제외한다.
- 실제 자료 전환 전에 복구 사본을 보존하고, 기존 로컬 DB를 바로 지우지 않는다.

프로그램 코드, Electron 실행 환경, 운영 라이브러리, 화면 자원과
`database/local/schema.sql`을 포함한다. 공개 설정은 `resources/desktop-config.json`에 둔다.
DB·Excel·사진·원본 보고서·백업·`.env`·로그인 세션·서명 키·서버 배포 자료는 제외한다.
`.git/`, `.superpowers/`, `artifacts/`, `tests/`, 개발용 `scripts/`, `supabase/`, `src/server/`,
Android 빌드 폴더·SDK·Gradle 캐시와 개발 전용 Node 의존성도 넣지 않는다.
현재 폴더 전체를 압축해 회사에 전달하지 않는다. 다만 `database/`를 통째로 빼면 안 된다.
PC 코드가 `database/local/schema.sql`을 읽기 때문이다.
설치본의 ASAR와 별도 자원, 실제 NSIS 내부 제품을 모두 검사하며
필수 자원 누락이나 승인되지 않은 파일·내용이 발견되면 릴리스를 확정하지 않는다.

Windows 사용자 자료 위치는 `%APPDATA%\Demo`다. 새 PC는 프로그램 계정으로 로그인하면
공동 서버에서 조회 사본을 받는다. PC별 초안·미전송 요청은 회사·계정별로 분리한다.
Mac의 `database-location.json`이나 로컬 DB를 회사 PC에 복사하지 않는다.

설치는 현재 Windows 사용자에게 적용하고 한국어 마법사와 바로가기를 제공한다.
수동 업데이트는 앱을 정상 종료한 뒤 새 설치본으로 진행한다. 기존 앱을 먼저 제거할 필요는 없다.
다운로드만 한 이전 EXE는 실행하지 않고 새 버전을 설치하면 된다. 사용자 자료 폴더를 삭제하지 않는다.
제거는 프로그램·바로가기만 정리하고 사용자 자료를 남긴다.
앱을 강제 종료해 DB를 지우거나, 오류를 해결하려고 자료 폴더를 초기화하지 않는다.

## Windows 인수 시험

아래 항목은 현재 모두 실기기 미실행이다. Mac 자동 검사 결과로 완료 처리하지 않는다.
자료를 바꾸는 시험은 운영 회사 대신 가짜 회사/계정으로 진행한다.
운영 첫 로그인은 기존 서버 자료 조회 중심으로 확인하고 실제 문자 발송은 자동 실행하지 않는다.

각 PC에서 `winver`의 OS 빌드, x64 여부, Windows 사용자/권한, 앱 버전,
설치본 SHA-256·서명 상태, 실행 날짜와 결과를 기록한다.
다운로드한 파일의 해시는 PowerShell에서 다음과 같이 확인한다.

```powershell
Get-FileHash .\Demo-Setup-0.1.9-x64.exe -Algorithm SHA256
```

## 회사 전체 배포 전

Windows 실기기 시험, 서명/실행 경고 처리 방식, 운영 지도·이동시간 경로,
납품 소스 복구 기준을 확인한 뒤 홈페이지에 검증한 설치본과 APK만 각각 게시한다.
홈페이지에는 버전·지원 OS·설치 안내·해시를 함께 제공한다.
소스 폴더·`.env`·DB·복구 사본을 다운로드 파일에 섞지 않는다.
홈페이지 게시와 자동 업데이트 서비스는 이번 구현에서 실행하지 않는다.

프로세스가 실행 중이면 설치·제거 모두 정상 종료 후 재시도/취소만 제공한다.
내장 종료 강제 실행을 사용하지 않으며, 상태 확인 오류도 설치 중단으로 처리한다.
프로세스 조회 반환 코드는 [NSIS nsProcess 문서](https://nsis.sourceforge.io/NsProcess_plugin)를 따른다.
