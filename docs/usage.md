# 프로그램 사용 안내

현재 구현된 기능을 설명합니다. 휴대폰 설정과 문자 발송은 [동기화 안내](sync.md), 지도 설정은 [지도 안내](maps.md)를 참고하세요.

## 현재 기능

업무 현황은 요청대로 빈 화면입니다. 고객 관리에는 전체 고객·신규 등록·거절 목록·삭제 목록 탭이 있으며, 정보 수정은 고객 상세 팝업에서 합니다.

- **전체 고객**: 처음에는 전체 고객을 표시합니다. **지역 >** 버튼을 누르면 상단의 **전체 / 북부 / 동부 / 서부**에서 업무 구역을 고를 수 있습니다. 북부를 누르면 **북부 전체**와 북부에 속한 시·군만 표시하며, 동부·서부도 같습니다. 구역 버튼은 선택지를 바꾸고, 아래의 구역 전체 또는 시·군 버튼을 눌러 고객 목록을 좁힙니다. 여러 구역·시군을 함께 선택할 수 있고 검색어도 함께 적용됩니다. 같은 시·군이라도 선택한 업무 구역에 저장된 묘지만 표시합니다. 구역 전체를 선택하면 그 구역의 개별 선택을 대체하고, 개별 시·군을 고르면 그 구역 전체 대신 시·군 선택으로 바뀝니다. 선택한 지역 칩을 눌러 해제하거나 **전체 → 전체 지역**으로 모두 해제합니다. 미지정 및 추가한 업무 구역도 조회할 수 있습니다. 지역 목록은 선택 뒤에도 열려 있고 바깥을 누르거나 Esc로 닫습니다.
- **통합 검색**: 전체 고객의 지역 선택 아래 검색창 하나에 입력하고 검색 버튼이나 Enter를 누르면 이름·전화번호·지역·묘지위치 등 표에 표시되는 정보를 함께 검색합니다. 부분 검색을 지원하고 전화번호는 하이픈·공백을 무시하므로 뒷자리만 입력해도 됩니다. 선택한 지역 안에서 검색하며, 전체를 선택하면 모든 지역을 검색합니다. 검색어를 지우면 선택한 지역의 전체 목록으로 돌아갑니다. 묘지 정보로 검색하면 일치한 묘지 행만 보여줍니다.

표는 **묘지별로 한 행**씩 표시합니다. 같은 고객의 묘지가 여러 개면 행을 나누며, 상단에 고객 수와 행 수를 함께 보여줍니다. 지역 선택과 지역 검색은 해당 지역의 묘지 행만 보여줍니다. 지역은 묘지 주소에서 분류하며 별도 지역 컬럼을 저장하지 않습니다. 묘지가 없는 고객도 미분류에 남습니다.

고객이 연결되지 않은 묘지도 `고객 미연결`로 표시하며 입금 내역을 함께 보여줍니다. 이 행은 고객 수에는 포함하지 않습니다.

표는 묘지위치, 좌표 유무, 기수, 평수, 이름, 전화번호, 전년도·올해 금액 순서로 표시합니다. **좌표 유무**는 현재 묘지 주소에 맞는 저장 좌표가 있으면 `O`, 없으면 `X`로 표시하며 숫자 좌표는 표시하지 않습니다. 표 아래 가로 스크롤로 전체 항목을 볼 수 있으며 모든 열이 함께 이동합니다.

금액 열은 전년도와 올해만 표시하며 새해에는 자동으로 바뀝니다. 금액을 입력·저장하기 전에는 새 연도의 DB 기록을 만들지 않습니다. 금액은 **DB 원본 숫자**를 그대로 표시하며 단위를 임의로 환산하지 않습니다. 같은 묘지·연도에 여러 종류의 금액이 있으면 각각 표시하고 날짜·방법·메모가 있으면 함께 표시합니다. 값이 없는 칸은 `—`, 실제 0은 `0`으로 구분합니다. 고객 DB의 연도별 금액은 청구 기준이며 실제 입금은 별도 청구·입금 기록에서 확인합니다.

## 고객 상세 조회·수정

전체 고객 목록의 행을 더블클릭하거나 키보드로 행에 초점을 맞추고 Enter를 누르면 상세 팝업이 열립니다. 처음에는 조회 화면으로 정보를 보여줍니다. **수정하기**를 누르면 같은 위치와 모양을 유지한 채 값의 글자만 편집할 수 있습니다. 편집한 뒤 **저장**하면 연결된 로컬 DB와 고객 목록에 즉시 반영됩니다. 편집 중 **취소**를 누르면 조회 화면으로 돌아가며 변경 내용은 저장하지 않습니다. 이름·전화번호는 고객 단위이고, 나머지 정보는 선택한 묘지에만 반영됩니다. 회사 연결이 되어 있으면 기존 자동 공유를 통해 휴대폰에도 반영됩니다.

연도별 금액이 여러 종류라면 각각 편집하고 기존 날짜·입금 방법·메모는 보존합니다. 기존 금액을 없애려면 0을 입력합니다. 기록이 없는 연도는 빈칸으로 남길 수 있습니다. 저장 전 `.demo-backups`에 DB를 백업하며, 오류 발생 시 변경 전체를 취소하고 팝업의 입력값을 유지합니다. 팝업을 연 이후 다른 곳에서 같은 정보를 수정했다면 덮어쓰지 않고 다시 열도록 안내합니다.

고객 상세에서 **삭제**를 누르면 고객과 연결된 모든 묘지가 **고객 관리 → 삭제 목록**으로 이동합니다. 고객 미연결 행은 선택한 묘지만 이동합니다. 원본 행·ID·금액·좌표·사진과 기존 작업·청구·입금 기록은 삭제하지 않습니다. 삭제 목록에서도 검색·지역 선택과 상세 조회가 가능하며, 상세의 **복원**으로 전체 고객에 되돌린 뒤 수정할 수 있습니다.

**삭제 목록 → 고객 상세 → 영구 삭제**는 확인 후 고객과 연결된 모든 묘지, 연도별 금액, 고객 DB의 연간 작업과 어스 위치를 제거합니다. 미연결 묘지는 선택한 묘지만 제거합니다. 삭제 목록에서 복원할 수 없으며, 삭제 전 자동 백업을 만듭니다. 연결된 KML·KMZ 파일도 현재 **Google Earth** 폴더에서 함께 제거합니다. 파일명과 저장된 원본 해시를 확인하고, 다른 고객이 공유하거나 내용이 바뀌었거나 원본을 검증할 수 없는 파일은 유지하며 결과에 안내합니다. 삭제 파일은 DB 백업 옆 `.db.earth-files` 폴더에 보관합니다. 별도 저장소의 청구·입금·작업 보고·사진, 앱 내부 및 클라우드의 원본 보관 사본과 백업은 유지합니다. 삭제 중에는 복원·닫기·중복 삭제를 막고, 실패하면 상세 창에서 다시 시도할 수 있습니다.

삭제 고객은 새 영업 대상, 고객 엑셀, 지도와 휴대폰의 고객·작업 위치 검색에서 제외됩니다. 삭제·복원은 회사의 기존 자동 공유로 전달되며, 오프라인 기기는 다시 연결된 뒤 반영됩니다. 휴대폰은 이 기능이 적용된 버전과 `customer-archive.sql` 서버 설정이 필요합니다. 기존 작업 확인·청구·입금 및 작업 보고 이력은 계속 확인할 수 있습니다.

## DB 연결

앱 전용 폴더의 `data/company.db`를 기본으로 엽니다. Mac은 `~/Library/Application Support/Demo`, Windows는 `%APPDATA%\Demo` 아래입니다. DB가 연결되지 않았다면 **고객 관리**의 연결 안내에서 **DB 파일 선택**을 누릅니다. 선택한 경로를 로컬에 기억합니다. 원본 DB를 교체하거나 외부에서 수정했다면 **새로고침**을 누릅니다.

일반 목록 조회는 읽기 전용입니다. **신규 등록 → 등록**을 누르면 연결된 DB에 새 고객과 묘지를 저장합니다. 기존 고객 관리 기능은 로컬 DB를 사용합니다. **설정 → 휴대폰 연동**에서 회사 클라우드로 로그인하고 동기화하면 고객·작업 자료와 청구·입금 기록을 전송합니다. 앱 목록은 연결한 DB 자료를 표시합니다. 요청에 따라 넣은 부천 100 테스트 자료도 현재 업무 자료에 포함되어 있으므로 임의 삭제하지 않습니다.

## 신규 등록

일반 신규 등록은 **등록 버튼을 눌렀을 때만** 실행합니다. 영업을 거절한 분은 이름·전화번호·묘지위치·고객 요구사항 등을 입력한 뒤 **거절**을 누르면 **고객 관리 → 거절 목록**에 저장하고 해당 목록을 엽니다. 입력 중 Enter를 눌러도 어느 쪽으로도 저장되지 않으며, 고객 요구사항의 Enter 줄바꿈은 유지합니다.

거절 목록에서는 지역·통합 검색과 고객 상세 조회·수정·삭제를 사용할 수 있습니다. 거절 기록은 일반 고객·Excel·영업 확인·작업 대상에서 제외하며, 연간 작업의 **미진행**과는 다른 상태입니다. 저장에 실패하면 입력을 유지합니다.

묘지위치, 기수, 평수, 이름, 전화번호, **금액 (원)**, **고객 요구사항**을 입력한 뒤 **등록**을 누릅니다. 각 항목은 선택 입력이며 이름·전화번호도 비워둘 수 있습니다. 아무 내용도 없는 폼은 등록하지 않습니다. 신규 등록에는 지역 입력란을 표시하지 않습니다. 지역은 묘지위치에 따라 회사의 경기 북부·서부·동부 기준으로 자동 분류해 저장하며 위치를 바꾸면 함께 갱신합니다. 분류 기준이 없는 주소는 미지정으로 둡니다. 평수는 0 이상의 숫자를 받습니다.

묘지위치는 **시·도 → 시·군·구**를 선택한 뒤 상세주소를 입력합니다. 예를 들어 `경기도 / 부천시 / 원미구 장말로 330`을 입력하면 `경기도 부천시 원미구 장말로 330`으로 합쳐 저장합니다. 경기도처럼 일반구가 있는 시는 시까지 선택하고 구·읍·면·동·번지는 상세주소에 적습니다. 세종특별자치시는 시·군·구 선택 없이 상세주소를 입력합니다. 주소를 전부 비운 채 다른 고객 정보만 등록할 수도 있습니다.

**어스 위치 가져오기** 창의 **어스 검색 주소**에 현재 전체 주소가 표시되며 수정할 수 있습니다. **구글 어스로 찾기**는 이 주소를 Google Chrome의 Google Earth 웹 검색으로 엽니다. Chrome이 없거나 실행에 실패하면 설치·실행 상태 확인 안내를 표시하고, 다른 브라우저로 대신 열지 않습니다. 수정값은 검색에만 사용하고 고객 DB의 묘지위치나 신규 등록 주소는 바꾸지 않습니다. 창을 다시 열면 현재 고객·등록 주소가 표시됩니다. 등록 전에도 이용할 수 있고 검색만으로 DB에 저장되지 않습니다. 지역 선택은 인터넷 없이 가능하며 구글 어스에는 인터넷 연결이 필요합니다. 이름·전화번호·금액은 검색에 전달하지 않습니다. 주소 검색용 API 키는 필요하지 않습니다.

직접 입력한 상세주소의 오타나 실제 묘지 위치는 자동 검증하지 않습니다. Google Earth에서 검색되지 않거나 넓은 지역으로 이동하면 해당 묘지를 직접 확인해야 합니다. 지도 핀은 고객 등록 후 기존 지도 처리 절차를 따릅니다.

### Google Earth 위치 파일 가져오기

현재 소스 폴더에서 실행하는 프로그램은 **데모 자동화 → Google Earth** 폴더를 사용합니다. 신규 등록 또는 고객 상세에서 **어스 위치 가져오기**를 열면 이 폴더를 자동 감지하며, 주소·날짜별 하위 폴더는 새로 만들지 않습니다. 별도로 배포한 설치형 앱은 운영체제의 **문서 → Demo → Google Earth** 폴더를 사용합니다.

1. **어스 위치 가져오기**를 연 뒤 **구글 어스로 찾기**로 묘역을 확인합니다.
2. Earth에서 점 또는 다각형 하나를 만들고 **KML·KMZ 파일 하나**를 해당 폴더에 저장합니다. 브라우저가 무조건 다운로드 폴더에 저장한다면 다운로드한 파일을 해당 폴더로 옮겨도 됩니다.
3. **구글 어스로 찾기**를 누른 뒤 해당 폴더에 새로 저장하거나 수정한 파일 중 마지막 파일을 감지해 **대표 좌표와 계산 면적**을 자동 반영합니다. 기존 고객은 좌표·경계·면적과 다각형에서 계산한 평수를 고객 DB에 바로 저장하고, 신규 고객은 다각형의 계산 면적을 평으로 환산해 평수에 소수 첫째 자리까지 자동 입력합니다. 점 파일은 면적이 없어 평수를 바꾸지 않습니다. **고객 이름은 항상 직접 입력합니다**(파일 이름은 이름 칸에 들어가지 않습니다). 좌표와 입력값은 고객 **등록**을 누를 때 함께 저장합니다.

**신규 등록의 묘지 코드(서버를 쓰는 회사)**: 신규 등록에서 **어스 위치 가져오기**를 열면 누가 등록하든 묘지 번호를 하나 예약하고 `데모-번호-글자` 코드를 팝업에 보여 주며 클립보드에 복사합니다. Earth에서 그린 KML의 파일 이름에 이 코드를 넣어 **내려받기** 폴더나 **Google Earth** 폴더(**폴더 열기** 버튼)에 저장하면, 그 코드가 든 파일만 자동으로 읽습니다(팝업을 열기 전에 저장한 것도 읽음). 마스터·부마스터가 **등록**하면 그 번호로 묘지가 만들어지고, 관리자·영업은 **검토 요청**으로 보냅니다. 등록이 끝나거나 **내용 지우기**·**선택 해제**를 누르면 그 코드로 저장한 KML 파일은 폴더에서 지워집니다. 이 PC의 고객 DB만 쓰는 회사는 코드 없이 위 방식으로 동작합니다.

같은 파일을 편집해서 다시 저장하거나 다른 이름으로 저장하면 열린 창에서 마지막 파일의 변경 내용도 자동 반영합니다. 같은 파일의 동일한 내용은 중복 저장하지 않습니다. **구글 어스로 찾기**를 다시 누르면 그 시점의 파일 상태를 새 기준으로 기록합니다. 검색 전에 있던 변경 없는 파일은 자동으로 가져오지 않으므로 **KML·KMZ 파일 선택**으로 직접 고릅니다. 후보가 여러 개면 파일의 마지막 변경 시각을 우선하고 같으면 수정 시각으로 최신 파일을 골라 저장이 끝난 뒤 읽습니다. 파일에 위치가 여러 개 있으면 Earth에서 위치 하나씩 별도 파일로 저장합니다. 직접 선택한 파일은 **적용/저장**을 눌러 반영합니다. **다시 읽기**로 저장 실패 후 재시도할 수 있습니다. 저장 후 평수는 고객 상세의 **수정**, 대표 좌표는 묘지 지도의 **위치 정보 저장**으로 수정할 수 있습니다. 경계와 계산 면적은 수정한 KML을 다시 가져와 갱신합니다.

**가져오기 창을 닫거나 로그아웃·DB 전환·앱 종료하면 자동 감지를 중단합니다.** 다음에 창을 열어도 같은 폴더를 쓰며, **구글 어스로 찾기**를 누른 뒤 새로 저장·수정한 파일만 자동 감지합니다. 이전에 만든 주소·날짜별 폴더와 원본 파일은 그대로 남습니다. 사용자가 파일을 직접 옮기거나 삭제해도 이미 DB에 저장한 좌표·면적은 남습니다. 고객의 일반 삭제·복원은 파일을 유지하고, **영구 삭제**만 검증된 연결 파일을 Google Earth 폴더에서 제거합니다. 원본 파일명과 확인·가져오기 시각은 계속 보관합니다. 읽은 원본은 앱 데이터 폴더의 `.demo-earth/originals`에도 복사합니다. DB와 이 폴더를 함께 백업하면 로컬에서 복구할 수 있습니다.

신규 등록 주소를 바꾸면 적용해둔 위치는 해제됩니다. 기존 고객 주소를 수정하면 이전 주소의 어스 자료라는 표시가 나오며 새 주소를 확인하고 다시 저장해야 합니다. 파일당 5 MB, 점 또는 다각형 하나, 도형의 전체 좌표 2,000개까지 가져올 수 있습니다. 선·복합 도형과 교차하는 다각형은 지원하지 않습니다. 다각형의 좌표는 도형 안의 대표 지점이고 면적은 ㎡·평으로 표시하는 구면 근사값이며, 측량 결과나 지형의 실제 표면적은 아닙니다.

저장한 **좌표·계산 면적은 자동 공유되어 휴대폰 고객 상세와 지도에 표시**됩니다. 승인한 현장 GPS가 있으면 그 좌표가 우선이며 고객의 평수는 바꾸지 않습니다. 주소가 바뀌면 이전 어스 좌표는 지도에서 제외됩니다. 원본 KML/KMZ는 비공개 R2 저장소에 버전별로 보관합니다. 인터넷이 끊기면 로컬 저장과 업로드 대기를 유지하고 재연결·앱 실행·포커스 복귀 시 재시도합니다. 고객 상세의 **원본 업로드 대기 / 원본 보관 완료**로 구분합니다. 기존에 좌표만 저장했던 자료는 원본 파일을 다시 가져와야 원본도 보관됩니다. 위성사진 촬영 기능은 포함하지 않습니다.

금액은 0 이상의 정수이며 `150,000`처럼 쉼표를 넣을 수 있습니다. 등록하는 해의 고객 기준 금액으로 저장하며 실제 입금으로 처리하지 않습니다. 비워두면 금액 기록을 만들지 않고, 0을 입력하면 0원으로 저장합니다. 고객 요구사항과 특이사항은 여러 줄로 입력할 수 있습니다. 전체 고객 표에는 표시하지 않으며, 고객 행을 더블클릭해 상세 창에서 확인할 수 있습니다. 고객 상세의 **수정하기** 또는 영업 확인에서 변경할 수 있습니다. 두 항목은 고객별로 유지되며 영업 확인에서 수정한 뒤 **저장**을 누르면 고객 DB와 고객 상세에도 반영됩니다.

등록은 새 고객과 묘지 한 행을 생성합니다. 같은 이름이 있어도 기존 고객을 덮어쓰거나 합치지 않습니다. 일반 **등록**은 고객 DB 저장과 함께 올해 작업을 **진행**으로 생성합니다. 작업 관리에 바로 표시되며 영업 확인에서 다시 입력할 필요가 없습니다. 작업 확인에는 작업 순서 설정을 마친 뒤 시트로 표시됩니다. **거절** 버튼으로 등록한 고객은 거절 목록에만 저장합니다. 등록 후 고객 목록과 지역 선택이 갱신됩니다. 저장 전에는 DB 옆 `.demo-backups`에 백업하며, 저장 중 오류가 나면 이번 등록 전체를 취소합니다. 실패한 입력은 화면에 남습니다.

## 작업 관리

작업 탭 사이를 이동할 때는 이미 받은 목록과 순서를 재사용합니다. 고객·보고·입금 변경 신호나 화면 재열기에서는 새로 조회하며, 조회 실패·저장 결과 확인 중인 순서는 다음 탭에서 다시 확인합니다. 공동 영업 배정 고객을 떠날 때는 확인 창에서 **입력 버리고 이동 / 저장하고 이동 / 취소**를 바로 선택합니다. 별도 통화 종료 체크박스는 없으며, 이동 버튼을 누르면 통화 종료 확인과 배정 해제를 처리합니다.

**영업 확인 / 작업 관리 / 작업 확인 / 작업 분배** 네 탭을 사용합니다. 영업 확인·작업 관리·작업 확인의 **지역** 버튼에서 고객 관리와 같은 방식으로 **전체 / 북부 / 동부 / 서부**를 고릅니다. 구역을 누르면 해당 시·군이 나타나며 **북부 전체**처럼 구역 전체 또는 개별 지역을 여러 개 선택할 수 있습니다. 저장된 묘지의 업무 구역을 기준으로 필터링하며, 같은 시·군이라도 다른 구역이면 섞이지 않습니다. 지역 선택은 각 탭에서 따로 유지하고 검색·상태 필터와 함께 적용합니다. 영업 확인에서 작성 중인 내용이 있으면 저장·취소 확인을 거친 뒤 지역을 바꿉니다. 영업 확인에서 **전체**를 선택하면 모든 지역의 미저장 고객을, 지역을 선택하면 해당 지역의 미저장 고객을 한 명씩 보여줍니다. 올해 전화 결과를 저장한 고객은 결과와 관계없이 영업 확인에서 빠지고 작업 관리에서 조회·수정합니다. 아직 결과를 저장하지 않은 고객의 전화 결과는 연락 X입니다. **이름 검색**에서 이름의 일부를 입력하고 Enter 또는 검색을 누르면 선택 지역의 영업 대상을 찾습니다. 지역을 아직 고르지 않았다면 전체 지역에서 검색하며, 검색어를 지운 뒤 검색하면 이름 필터를 해제할 수 있습니다. 검색한 결과 안에서도 이전·다음 고객으로 이동할 수 있고 작성 중인 내용은 이동 전에 저장·취소 확인을 거칩니다.

고객 요구사항·특이사항은 왼쪽에 세로로, 올해 금액·작업 기한은 오른쪽에 표시합니다. 저장 버튼 왼쪽의 전화 결과 토글에서 **연락 X / 진행 / 미진행**을 선택합니다. 고객 이름·묘지 주소·전화번호·기수·평수·**전년도 금액**을 보고 통화한 뒤 전화 결과와 **올해 금액 / 고객 요구사항 / 특이사항 / 작업 기한**을 입력합니다. 기한은 “추석 전까지”, “다음 주 중”처럼 최대 200자의 글로 입력하며 그대로 저장합니다. 날짜로 자동 변환하지 않습니다. 금액은 원 단위이며 쉼표를 넣을 수 있습니다. 메모와 기한은 비울 수 있고, 올해 금액 기록이 없으면 빈칸으로 저장할 수 있습니다. 기존 금액을 없애려면 0을 입력합니다. **저장**을 누르면 저장한 뒤 다음 대상 고객으로 넘어갑니다. 마지막 고객의 기록도 저장할 수 있습니다. 저장하지 않은 입력으로 지역·탭·고객을 바꾸면 저장, 버리기, 계속 입력 중 선택합니다. 저장 실패 시 입력을 유지합니다.

**진행·미진행·연락 X 모두 저장하면 작업 관리에 추가됩니다. 작업 확인에는 작업 순서 설정을 마친 시트의 진행 작업만 표시됩니다.** 아직 저장하지 않은 고객은 두 목록에 넣지 않습니다. 작업 관리에서는 **전체 / 진행 / 미진행 / 연락 X** 필터로 저장된 결과를 조회합니다. 표는 성함, 연락처, 묘지위치, 기수, 특이사항, 작업 기한, 이번년도 금액, 등록 순서이며 등록 칸에 전화 결과를 표시합니다.

작업 관리의 검색창은 이름·주소·연락처·특이사항·기한 등 표시된 정보로 목록을 좁힙니다. 검색과 전화 결과 필터를 함께 사용할 수 있습니다. 행을 더블클릭하거나 선택한 셀에서 Enter를 누르면 작업 상세가 열립니다. **수정하기**를 누르면 전화 결과·올해 금액·고객 요구사항·특이사항·기한을 같은 줄에서 편집하고 **저장**하면 고객 DB와 두 표에 반영됩니다. 기본 이름·주소·연락처는 고객 관리에서 수정합니다. 수정 중 **취소**는 저장 전 값으로 돌아가며, 저장 실패·충돌 시 입력값을 유지합니다. 수정해도 영업 확인에 다시 추가되거나 기존 작업 ID·금융 기록이 지워지지 않습니다.

작업 관리의 성함 앞 **등록 경로** 열은 신규 등록으로 생성한 작업에 **신규 등록**을 표시합니다. 기존 작업은 확인 가능한 신규 등록 KML 연결 기록이 있을 때만 표시하며, 출처를 확인할 수 없으면 빈칸으로 둡니다. 이 표시는 금액이나 작업 상태를 변경하지 않습니다. PC 0.1.3과 `20261019-work-registration-origin` 서버 업데이트가 필요합니다.

작업 관리 행을 더블클릭하면 열리는 작업 상세 창에서 **닫기 왼쪽의 삭제**를 누르면 확인 후 해당 연도의 작업만 목록에서 제거합니다. 수정 중에는 삭제 버튼을 숨깁니다. 고객 정보·묘지·기준 금액·청구 및 입금 이력·다른 연도 작업은 유지합니다. 현재 고객은 영업 확인에 연락 X 상태로 다시 표시됩니다. 삭제 목록으로 옮긴 고객의 남은 작업도 삭제할 수 있으며, 고객은 삭제 목록에 유지합니다. 작업 번호나 수정 버전이 달라졌다면 계속 충돌을 안내합니다. 영업 확인에서 다시 저장하면 기존 작업 ID를 사용해 재등록합니다. 이미 삭제한 작업에도 같은 규칙이 적용됩니다. 공유 서버에서는 `20261018-work-sales-search` 업데이트가 필요합니다.

작업 확인은 **작업 순서 설정을 완료해 저장한 시트**만 표시합니다. 진행으로 저장하는 것만으로 전체·지역별 시트를 자동 생성하지 않습니다. 저장한 시트가 없으면 작업 관리에서 작업 순서를 설정하라는 안내를 표시하며, 시트를 지워도 진행 작업은 작업 관리에 남습니다. 첫 저장 시트를 기본 선택하고 다른 시트로 이동했다가 돌아오면 선택을 유지합니다. 지역 필터는 해당 지역의 작업이 포함된 저장 시트를 찾으며, 표는 선택한 시트의 전체 방문 순서와 번호를 유지합니다. 전체·문자 발송 완료·입금 완료·입금 미완료 필터는 선택한 시트 안에서 적용합니다. 특이사항·작업 기한, 올해 금액, 문자 전송, 실제 입금 금액, 입금 완료를 함께 표시합니다. 발송 금액은 성공한 청구를 기준으로 반영하고, 전액 입금되었을 때만 입금 완료를 표시합니다. 미진행이나 연락 X로 바꾸면 작업 확인에서는 숨기고 작업 관리에는 유지합니다. 기존 청구·입금 이력과 작업 ID는 보존합니다.

고객 한 명당 연도별 작업 한 건입니다. 기본 정보가 바뀌어도 고객·묘지 ID와 작업 UUID로 연결합니다. 연간 기록은 재실행 후에도 유지되며 기존 자동 공유를 통해 활성 작업을 휴대폰 검색 자료에 전달합니다. 지역별 방문 순서는 아래의 **카카오 이동시간으로 작업 순서 만들기**를 사용합니다. 이전에 가져온 엑셀 원본·작업 사본·시트 자료는 보관하지만 새 작업 목록을 만드는 원천으로 사용하지 않습니다.

## 휴대폰 작업 보고·배정 작업·작업 확인

- 휴대폰의 단독 **작업 보고** 등록 화면은 없앴습니다. 작업 사진은 **배정 작업**에서 묘지를 눌러 올립니다(아래 '시트를 작업자에게 공동 배정하기').
- **작업 확인 → 보고 작업**에서 모든 계정이 회사의 보고 목록과 사진을 조회합니다. 등록 화면과 목록은 분리되어 있으며, 작업 확인은 처음에 보고 작업 탭으로 열립니다. 사장님·마스터에게는 **청구·입금 기록** 탭도 표시하며, 그 안에서 **청구 목록 / 입금 문자**를 선택합니다. 일반 작업자는 청구·입금 기록에 접근할 수 없습니다.
- 보고 목록은 보관된 자료를 먼저 표시하고 진입·변경 알림 때 자동 갱신합니다. 평소 **목록 불러오기** 버튼은 없으며, 연결 오류가 생기면 **다시 시도**를 표시합니다. 데스크톱 작업 보고도 자동으로 불러오고 오류 때만 다시 시도할 수 있습니다. 이전 보고는 **더 보기**로 조회합니다.
- 보고에서 고객을 확인해 청구를 저장하거나 이미 만든 청구를 다시 열면 **작업 확인 → 청구·입금 기록 → 청구 목록**의 해당 청구 상세로 이동합니다. 기존 문자 최종 검토·발송·입금 확인 절차는 유지합니다.
- 입금 확인 기록, 전액 입금 뒤의 **입금 완료 / 최종 문자 발송**, **입금 문자**의 보류 문자 확인은 [휴대폰 업무 흐름](sync.md#실제-업무-흐름-사장님-계정)을 따릅니다.

## 고객 목록을 엑셀 화면으로 보기

고객 관리의 **엑셀로 보기**는 앱 내부에 편집 팝업을 엽니다. 열 문자·행 번호·셀 값 입력줄과 하단 지역별 시트를 표시하며, 선택한 지역 시트부터 열립니다. 전체 고객 DB를 사용하고 고객 검색어로 시트 내용을 제한하지 않습니다. 팝업을 여는 것만으로 파일을 생성하거나 Excel·Numbers를 실행하지 않습니다.

셀을 직접 편집하거나 여러 칸을 붙여넣고 실행 취소·다시 실행할 수 있습니다. **DB 저장**을 눌러야 수정 내용을 반영합니다. 저장 전 백업을 만들고 여러 행을 한 번에 저장하며, 중간 오류나 외부 변경 충돌이 있으면 전체 저장을 취소하고 편집 내용을 유지합니다. 같은 고객의 이름·전화번호는 연결된 다른 묘지 행에도 함께 반영됩니다. 주소의 지역을 수정하면 DB 저장 후 해당 지역 시트로 이동합니다. 한 연도에 여러 금액 기록이 있으면 각각의 금액을 수정하며 기존 메모·입금일 등은 보존합니다. 기존 금액은 빈칸 대신 0으로 변경합니다.

**다운로드**를 누르면 저장 위치를 선택하여 현재 편집 내용이 포함된 `.xlsx` 파일을 저장합니다. 다운로드는 DB 저장과 별개이며 DB 미저장 상태를 해제하지 않습니다. 지역별 시트, 자동으로 늘어나는 연도, 열 순서, 전화번호 앞의 0을 유지합니다. 팝업에서 다운로드한 파일은 Excel 또는 Numbers로 열 수 있습니다. 앱 내부 편집기는 고객 정보 편집용이며 Excel의 수식 계산·차트·행 추가 기능은 제공하지 않습니다.

## 사이드바

사이드바 경계를 마우스로 드래그해 너비를 조절합니다. 좁히면 아이콘만 표시하며, 너비와 접힘 상태는 기기에 저장됩니다.

## 서버 사용량 바로가기

데스크톱 **설정 → 서버 사용량**을 펼치면 Cloudflare R2와 Supabase 사용량 바로가기가 나타납니다. 선택한 서비스의 공식 화면을 기본 브라우저로 엽니다. 브라우저에서 서비스 계정 로그인과 계정·조직 선택이 필요할 수 있습니다. 앱은 별도 사용량 조회 키를 저장하거나 자동 조회하지 않습니다.

## 직원 계정 관리

데스크톱 **설정 → 직원 계정 관리**는 별도의 휴대폰 연동 창을 열지 않고 메인 화면 안에서 표시됩니다. 처음 진입하면 등록한 직원을 조회하고, 이후에는 **새로고침**으로 갱신합니다. 직원 이름·아이디·비밀번호·권한을 입력하여 발급하거나 목록에서 권한 변경, 사용 중지·재개, 삭제를 할 수 있습니다. 삭제는 사장님·마스터만, 부마스터는 관리자·영업·일반 작업자 계정만 관리하며, 관리자는 목록만 봅니다([계정 관리](access.md)). 실제 계정은 기존 Supabase에 저장됩니다. 발급한 비밀번호는 저장하지 않으며 발급 성공 또는 화면 이동 시 입력란에서 지웁니다. 휴대폰 설정과 휴대폰 연동 창에는 직원 계정 관리가 표시되지 않습니다.

### 묘지별 최신 KML·KMZ

묘지에 새 파일을 가져와 정상 저장하면 최신 파일로 연결합니다. 앱이 관리하는 로컬 보관 폴더와 Google Earth 폴더에서 이전 연결 파일을 정리하며, 다른 묘지·다른 DB·등록 초안이 함께 쓰는 파일과 내용이 바뀐 파일은 유지합니다. R2는 새 파일의 업로드와 검증이 끝난 뒤 이전 원본을 정리합니다. 오프라인에서는 이전 R2 원본이 유지되며, 연결 후 최신 파일만 업로드하고 정리를 재시도합니다. 고객 한 명에게 묘지가 여러 곳이면 묘지별로 최신 파일 1개씩 유지합니다. 복구용 백업은 별도로 보존합니다.

## 묘지별 관리 표시와 업무 지역

고객 목록의 `관리`는 올해 작업 진행 여부와 별개로, 회사가 꾸준히 관리하는 묘지를 뜻합니다. 해당 묘지 상세 → 수정 → 관리 중을 체크하고 저장하면 그 묘지의 행 글자가 파란색으로 바뀌고 `관리 중` 문구가 표시됩니다. 같은 고객의 다른 묘지에는 자동 적용하지 않습니다.

`지역`에는 경기 북부·경기 서부·경기 동부를 선택하거나 새로운 구역명을 직접 입력할 수 있습니다. 저장한 구역명은 선택 목록에 이어 표시합니다. 기존 주소에서 계산한 파주·고양 등의 행정구역과 별도로 저장하며, 기존 지역 필터와 지도 구분은 유지합니다. 전체 검색에서 업무 지역과 `관리 중`도 검색할 수 있습니다.

기존 자료는 관리 체크 없음·지역 미지정으로 시작합니다. 기존 DB 조회는 파일을 변경하지 않으며, 처음 등록/수정 저장 시 검증된 변경 전 백업을 만든 뒤 두 컬럼을 추가합니다. 백업이나 저장에 실패하면 컬럼 추가와 값 변경을 함께 취소합니다. 신규 등록 화면에서도 두 항목을 입력할 수 있습니다. 현재 서버를 공동 DB로 전환할 때는 `20261017-grave-management`까지 준비된 SQL을 적용해야 새 항목을 보존합니다.

### 2026-10-17 묘지 주소에 따른 업무 지역 일괄 분류

현재 등록 자료의 빈 업무 지역을 아래 회사 기준으로 채웁니다. 북부는 경기도의 북부 10개 시·군을 참고했으며, 서부·동부와 서울·인천의 편입은 회사 업무용 분류입니다. 공식 행정구역 구분을 의미하지 않습니다.

| --------- | -------------------------------------------------------------------------------------- |
| 경기 북부 | 고양·파주·의정부·양주·동두천·포천·연천·남양주·구리·가평                                |

## 카카오 이동시간으로 작업 순서 만들기

작업 관리의 **작업 순서 설정**에서 지역을 여러 개 선택하고 시작할 묘지를 고른 뒤 **순서 만들기**를 누릅니다. 선택 지역의 진행 작업만 기존 KML/승인 좌표로 계산합니다. 결과는 작업 확인의 `부천/시흥` 같은 시트에서 순서 번호와 함께 표시됩니다. 마지막 묘지에서 종료하며 돌아오는 동선이나 작업 시간은 포함하지 않습니다.

위치가 없으면 KML 확인이 필요합니다. 주소로 묘지 위치를 추정하거나 작업을 조용히 제외하지 않습니다. **다시 계산**은 추가 대기 작업까지 포함해 순서 전체를 처음부터 다시 정하고 NEW 표시를 지웁니다. 누르기 전에 확인 창이 뜨며, 몇 곳만 늘었다면 아래처럼 끼워 넣는 것이 낫습니다. 계획만 지우려면 **순서 삭제**를 사용합니다. 문자·입금 필터로 행이 줄어도 원래 방문 번호를 유지합니다. 카카오 키와 회사 서버 업데이트는 [지도 설정](maps.md)을 참고하세요.

저장된 시트를 선택한 뒤 **전체 순서 지도**를 누르면 기존 구글 지도에 시트와 같은 방문 번호를 표시합니다. 모든 위치를 한 화면에 맞추고 `1 → 2 → 3` 순서로 화살표 직선을 연결합니다. 연결선은 순서를 보여주는 선이며 실제 도로 경로가 아닙니다. 같은 좌표의 작업은 한 핀에 `1, 2`처럼 해당 번호를 함께 표시합니다. 핀을 누르면 고객과 주소를 확인하고, **전체 보기**로 모든 위치를 다시 볼 수 있습니다. 지도 조회는 저장한 좌표와 순서를 사용하며 카카오 이동시간을 다시 요청하지 않습니다. 위치가 누락된 작업이 있으면 원래 방문 번호를 유지하고 누락 건수를 안내하며 연결선은 생략합니다. 작업이나 순서가 변경되면 지도를 지우고 시트 확인·재계산을 안내합니다.

작업 확인 표에서 작업 행을 **더블클릭**하거나 셀에서 **Enter**를 누르면 **방문 순서 수정** 팝업이 열립니다. 팝업에서는 이동할 순서만 입력할 수 있습니다. 예를 들어 5번을 2번으로 저장하면 5번 작업이 2번이 되고, 기존 2~4번은 3~5번으로 한 칸씩 이동합니다. 반대로 앞 작업을 뒤로 옮기면 그 사이의 작업이 앞으로 당겨집니다. 첫 작업을 옮기거나 다른 작업을 1번으로 옮기면 시작점도 함께 바뀝니다. 순서는 1부터 시트의 전체 작업 수 사이 정수로 입력합니다.

**전체 순서 지도**에서도 핀을 **더블클릭하거나 Enter**를 누르면 같은 팝업으로 순서를 수정합니다. 같은 좌표에 작업이 여럿이면 수정할 작업을 목록에서 고릅니다. 저장 후 표의 번호와 열린 지도의 핀·연결선을 함께 갱신하며, 현재 배정된 작업자는 유지하고 휴대폰 **배정 작업**에도 새 순서를 자동 반영합니다. 배정자를 다른 화면에서 바꾸거나 해제했다면 최신 배정 상태를 따릅니다. 순서만 이동할 때는 카카오 경로를 다시 조회하지 않습니다. 수동 변경 전의 예상 이동시간을 새 순서의 예상값으로 표시하지 않습니다. 저장 실패는 입력을 유지하고, 순서는 저장됐지만 작업자 반영이 확인되지 않으면 별도 안내를 표시합니다. 반영 요청은 기기에 보관하므로 연결이 돌아온 뒤 **작업 분배**를 다시 불러오면 재시작 후에도 최신 작업자에게 반영합니다. 순서를 새로 계산한 시트나 취소된 변경에는 이전 반영 요청을 적용하지 않습니다.

### 시트에 작업 끼워 넣기 (추가 대기)

시트를 만든 뒤 새로 진행으로 바뀐 작업은 시트 위쪽의 **추가 대기 N곳** 목록에 나타납니다. 시트와 배정은 그대로 쓸 수 있습니다. 작업 옆의 **번호 정해 추가**를 누르면 순서 지도에 새 작업 핀과 번호 핀이 함께 나오고, 앞에 올 핀을 누르면 그 다음 번호가 들어간 순서 수정 창이 열립니다. 번호는 직접 입력해도 되며 기본값은 맨 뒤입니다. 그 뒤 번호는 한 칸씩 밀리고, 넣은 작업은 구분 칸에 **NEW**로 표시됩니다. 사진 보고와 배정은 번호가 아니라 작업 ID로 연결되므로 번호가 밀려도 섞이지 않습니다.

추가는 마스터·부마스터·관리자가 합니다. 순서 수정 창의 **이 시트에서 빼기**는 마스터만 쓸 수 있고, 뺀 작업은 다시 추가 대기에 나타납니다. 삭제되거나 진행이 취소된 작업은 시트에서 자동으로 빠지고 나머지 순서는 그대로입니다. 주소·위치만 바뀌어도 순서를 유지합니다. 순서를 만든 지역은 **작업 순서 설정**의 지역 선택에서 빠지므로, 새 작업은 해당 시트의 추가 대기에서 넣습니다. 공동 모드로 전환하지 않은 로컬 회사에서는 삭제된 작업만 자동으로 빠지고, 진행이 취소된 작업이 남으면 **시트 확인 필요**가 표시됩니다.

## 시트를 작업자에게 공동 배정하기

PC **작업 관리 → 작업 분배**에서 저장된 순서 시트와 발급한 작업자 계정을 각각 여러 개 선택하고 **공동 배정**을 누릅니다. 시트 2개와 작업자 2명을 고르면 두 작업자가 모두 두 시트를 봅니다. 이름 옆의 로그인 ID로 계정을 구분할 수 있습니다. **배정 변경**은 선택한 시트의 공동 담당자 전체를 새 선택으로 바꾸고, **배정 해제**는 해당 시트를 담당자 화면에서 제외합니다. 순서 시트 자체는 유지합니다.

휴대폰에서는 하단의 **배정 작업** 탭을 엽니다. 로그인한 작업자에게 배정된 시트만 표시하며 시트를 누르면 정한 순서대로 묘지 주소를 확인할 수 있습니다. 묘지 주소를 터치하면 방문 번호·주소·저장된 KML 좌표의 카카오 위성 지도와 사진 보고를 한 화면에서 확인합니다. 위치를 다시 검색하지 않고 사진을 선택해 등록합니다. 일반 작업자도 본인에게 현재 배정된 작업에서 사진을 등록할 수 있으며 고객명·연락처·금액은 표시하지 않습니다. 고객·묘지 연결은 서버가 작업 번호로 확정하고, 사장님·마스터의 보고 목록과 상세에는 연결된 고객명·보고자·사진을 함께 표시합니다. 같은 주소의 다른 묘지와 혼동하지 않습니다. 사진 초안은 계정·시트·작업별로 따로 보관하며 실패하면 같은 보고로 재시도합니다. 배정 해제·작업 삭제·계정 중지는 서버가 등록과 완료 시 다시 검사합니다. 지도 연결 실패는 사진 보고를 막지 않으며 **지도 다시 연결**로 재시도할 수 있습니다.

시트의 순서를 고치거나 작업을 넣고 빼면 배정도 같은 순서로 바뀌고 휴대폰에 자동 반영됩니다. 공동 모드 회사는 **다시 계산**해 저장해도 배정이 새 순서를 따릅니다. 휴대폰에서는 넣은 작업에 **새로 추가**가 붙고, 순서가 바뀌면 "순서가 바뀌었습니다" 안내가 한 번 나옵니다. 시트를 삭제하거나 시트가 비면 휴대폰에 **재배정 필요**가 표시되므로 PC에서 다시 배정해주세요. 로컬 자료를 쓰는 회사에서는 다시 계산한 시트도 **재배정 필요**가 되며, PC 변경 사항이 서버에 동기화된 뒤 휴대폰에 반영됩니다. 통신 중 결과를 받지 못했을 때는 새로고침하면 같은 배정 요청으로 결과를 확인합니다.

실제 사용에는 `20261018-work-sheets` 이후 `20261018-work-task-reports` 서버 업데이트, `work-reports` Edge Function 배포와 새 휴대폰 앱 빌드 설치가 필요합니다. 이번 개발 검증에서는 운영 서버 배포·휴대폰 설치·실제 계정 배정을 실행하지 않았습니다.
