# 묘지 위치·경계 입력 재설계 (Google Earth 중심 자동화)

상태: 2026-10-22 사용자 답변을 반영한 3차 초안. 구현 전 검토 대기이며 제품 코드·운영 서버·실제 자료는 변경하지 않았다. R2 저장 규칙은 [R2 사진·KML 저장·보관·삭제 설계](2026-10-22-r2-storage-lifecycle-design.md)를 따른다.

변경 이력:

- 1차(받은 파일함 + 수동 확인): 손이 많이 가서 폐기.
- 2차(앱 안 Google 위성지도 그리기를 기본): Google 위성지도는 확대 배율이 낮아 산속 묘지를 정확히 판단할 수 없어 폐기.
- 3차(이 문서): **Google Earth에서 그리는 방식을 유지**하고, 그 앞뒤의 파일 처리·고객 연결·다음 묘지 이동을 앱이 자동으로 한다.

## 1. 목적과 사용자 요구

- 위치 입력은 **영업 통화 중·직후**, **신규 등록**, **기존 고객 일괄 입력**(300여 묘지)에서 한다. 신규는 한 달 10~50건이다.
- 산속 묘지까지 찾아야 하므로 확대가 잘 되는 정확한 위성사진이 필요하다. DMZ 인근도 보여야 한다. 그래서 Google Earth를 쓴다.
- 손이 최대한 덜 가야 한다.
- 면적(다각형)은 항상 정한다. 면적을 정한 위치를 이미지로 남기고 싶다(회사 내부에서만 사용).
- 고객을 지우면 위치 자료도 함께 정리돼야 한다.

## 2. 핵심 결정

1. **그리기는 Google Earth, 나머지는 앱.** 사람은 Earth에서 경계를 그리고 내보내기만 한다. 주소 찾기, 파일 찾기, 고객 연결, 저장 후 정리, 다음 묘지 열기는 앱이 한다.
2. **묘지 코드로 자동 연결.** 앱이 Earth를 열 때 묘지 코드(예: `데모-328-K`)를 클립보드에 넣는다. 사용자는 Earth에서 KML 파일(프로젝트) 이름에 Ctrl+V만 한다. 2026-10-22 사용자 결정: **DB의 묘지 행과 KML 파일을 묘지 고유 번호로 묶고, 그 번호를 파일 이름으로 저장해 연동한다.** 코드가 든 파일은 다른 고객 창이 열려 있어도 그 묘지에만 들어간다.
3. **기다리는 묘지가 하나뿐이면 코드도 필요 없다.** 앱에서 Earth를 연 묘지가 하나뿐이면, 그 뒤 처음 들어오는 KML을 그 묘지 것으로 본다. 둘 이상이면 코드로 구분한다.
4. **면적 필수, 묘지당 현재 경계 1개.**
5. **위치 이미지는 Earth가 만든 이미지로 남긴다.** 출처 표시가 들어간 Earth의 이미지 저장 기능 또는 화면 캡처를 앱이 받아서 KML과 함께 보관한다(7장). 앱이 지도 API를 자동 캡처하는 방식은 쓰지 않는다.

### 묘지 코드의 정의

- 형식: `데모-{묘지 번호}-{확인 글자}` (예: `데모-328-K`). 묘지 번호는 묘지가 DB에 처음 생길 때 정해지는 기존 묘지 ID이고, 삭제된 번호는 다시 쓰지 않는다. 확인 글자는 번호에서 계산한 한 글자로, 손으로 잘못 고친 코드가 다른 묘지와 맞지 않게 한다.
- Earth를 열 때 새로 만드는 값이 아니다. 같은 묘지는 언제 Earth를 열어도 같은 코드다.
- 묘지 번호는 서버 번호표(`id_counters`, 증가만 함)에서 받는다. 다른 고객이 일반 삭제·영구삭제되거나 묘지가 지워져도 남은 묘지의 번호는 바뀌지 않고, 지워진 번호를 새 묘지에 다시 주지 않는다. 화면의 방문 순서 번호나 구분 번호와는 다른 값이다.
- 신규 등록처럼 아직 묘지가 DB에 없으면, **구글 어스로 찾기를 누르는 순간 서버가 새 묘지 번호를 예약**해 그 번호로 코드를 만든다(현행 공동 모드의 고객/묘지 번호 예약·준비 ID 재사용). 등록하면 그 번호로 묘지가 만들어지고 위치가 함께 저장된다. 등록을 취소하면 예약 번호는 쓰지 않고 버린다(번호를 재사용하지 않으므로 빈 번호가 생길 뿐 다른 묘지와 섞이지 않는다). 예약은 24시간 뒤 자동 취소된다.
- 코드는 파일 이름에 넣는 것이 기본이다. 앱은 파일 이름을 먼저 보고, 없으면 KML 안의 경계·프로젝트 이름도 찾는다. 브라우저가 붙이는 `(1)` 같은 꼬리는 무시한다.
- 저장하면 묶음은 세 군데에 고정된다: 서버 DB의 묘지 행 ↔ 위치 버전(파일 SHA-256 포함), R2 경로 `earth/{작업공간}/{묘지 번호}/{버전}/original.kml`, 앱 보관 사본 이름. 사용자가 나중에 원래 파일 이름을 바꾸거나 지워도 묶음은 깨지지 않는다.
- Google Earth와 계속 연결되는 것은 아니다. Earth에서 나중에 경계를 고쳐도 앱에 자동 반영되지 않는다. 고친 경계를 같은 코드로 다시 내보내면 새 버전으로 교체된다.
- 영구삭제한 묘지의 코드로 파일이 들어오면 연결하지 않는다.
- 코드에는 고객 이름·전화번호를 넣지 않는다.

### 스크린샷 업로드 (2026-10-25)

팝업에 붙여넣은 스크린샷은 KML과 **같은 버전**으로 올라간다. 앱이 준비 요청에 스크린샷의 해시와 크기만 보내면 서버가 매니페스트에 `screenshot`으로 적고, 키(`earth.jpg`)를 KML·매니페스트와 함께 한 번에 예약한다. 올리는 파일은 JPEG 한 장(5MB 이하)이며 서버가 크기·해시·JPEG 머리말을 다시 확인한 뒤에야 버전을 완료한다. 스크린샷이 없는 버전은 그대로이고, 퇴역·영구삭제 때는 예약된 키 목록이 정리 대상이라 `earth.jpg`도 함께 지워진다.

### 신규 등록 위치 파일의 폴더 (2026-10-25)

마스터·부마스터·사장님이 바로 등록할 때는 파일을 올리는 시점에 묘지가 아직 DB에 없다. 폴더 이름은 올리는 순간 정해지고 옮기지 않으므로, 앱이 준비 요청에 **등록 화면의 사업지역(`businessRegion`)** 을 함께 보내고 서버가 이 값과 주소로 `묘지/{사업지역}/{시군}/{묘지번호}/위치/…`를 정한다(`database/cloud/privacy/storage-keys.sql`의 plan). 사업지역을 비웠으면 `미분류`다. 등록을 확정할 때 서버가 주소와 사업지역이 준비 때와 같은지 확인하고 다르면 거절한다. 검토 요청은 승인할 때 묘지가 생기므로 그때 지역 폴더가 정해진다.

### 신규 등록의 단계와 정리

2026-10-22 사용자 결정: 신규 등록은 영업·관리자가 **검토 요청**을 확정하고, **마스터·부마스터가 승인**해야 DB에 들어간다(권한 체계는 별도 권한 설계에서 정한다). 위치 자료는 이 단계를 그대로 따른다.

| 단계      | 누가                         | KML·스크린샷 위치                        | 자동 정리                                                               |
| --------- | ---------------------------- | ---------------------------------------- | ----------------------------------------------------------------------- |
| 작성 중   | 영업·관리자                  | 앱 임시 칸, R2 `staging/`                | 묘지 번호 예약 후 24시간 안에 검토 요청을 하지 않으면 모두 삭제         |
| 검토 대기 | 영업·관리자가 검토 요청 확정 | R2 `review/`(요청자 PC 사본은 이때 삭제) | 승인·반려까지 보관. 권한 설계 8장의 장기 미처리 기한이 정해지면 그 기한 |
| 승인      | 마스터·부마스터              | R2 정식 묘지 폴더로 이동, 이때 DB 등록   | 일반 위치 규칙                                                          |
| 반려      | 마스터만                     | 즉시 모두 삭제                           | —                                                                       |

- 승인자는 검토 화면에서 KML 경계·스크린샷·면적을 보고 판단한다.
- 작성 중 자료와 검토 대기 자료는 NAS 백업에 넣지 않는다(DB에 등록된 자료만 백업). R2 `staging/`은 1일 자동 만료, `review/`는 만료 없음이며 둘 다 백업 대상이 아니다.
- **영업·관리자가 작성 중에 취소**하면 "그린 위치와 스크린샷도 함께 삭제됩니다"를 안내한 뒤 즉시 지운다: 예약, 사용자 폴더(내려받기·Google Earth)에 남은 그 코드의 KML·이미지, 앱 임시 사본, R2 임시 파일.
- **24시간 만료**: 서버가 예약을 취소하고 R2 임시 파일을 지운다. PC에 남은 파일은 앱이 다음에 켜지거나 동기화할 때 같은 코드로 찾아 지운다. 만료 1시간 전에 열린 등록 창에 "검토 요청을 하지 않으면 그린 위치가 삭제됩니다"를 알린다.
- **검토 요청 순간**: 요청자는 그 뒤로 자기 자료를 볼 수 없으므로(권한 설계 4.1), 요청자 PC의 KML·스크린샷 사본과 사용자 폴더에 남은 그 코드의 파일을 지운다. 자료는 서버 `review/`에만 남는다.
- **반려**: **마스터만** 할 수 있다(2026-10-22 사용자 결정, 부마스터는 승인만). 반려하면 즉시 요청 내용·예약 번호·`review/` 파일을 지운다. 요청자에게 알리지 않는다(2026-10-22 사용자 결정). 다시 하려면 처음부터 새로 등록한다(새 번호 예약).
- 예약 번호는 다른 묘지와 겹치지 않으므로 이 정리가 등록된 묘지의 자료를 지우지 않는다. 반려·취소된 번호는 다시 쓰지 않는다.
- 기존 고객 위치를 관리자가 바꿀 수 있는지는 4.4와 권한 설계에서 정한다. 관리자 변경을 검토 요청으로 받기로 하면 같은 검토 대기 단계를 재사용한다.

## 3. 현재 흐름과 문제 (요약)

- 고객 창 → **구글 어스로 찾기**(Chrome으로 `earth.google.com/web/search/{주소}` 열기, `earth-link.cjs`) → Earth에서 그리기 → KML 저장 → 내려받기 폴더라면 Google Earth 폴더로 직접 옮기기 → 앱이 그 폴더의 **가장 최근 파일**을 열린 고객에게 적용하고, 기존 고객은 확인 없이 바로 저장(`earth-files.cjs`).
- 고객 A 창을 연 채 고객 B 파일을 저장하면 B의 위치가 A에 들어간다.
- 지점 파일도 받아 면적이 빠질 수 있다.
- 기존 고객을 몰아서 입력하는 화면이 없다.
- 한 KML이 사용자 폴더·앱 보관 폴더·로컬 DB·서버 DB·R2·영구삭제 복구 사본(`.earth-files`)에 남고, 정리 규칙이 사본마다 다르다.

## 4. 기본 흐름

### 4.1 한 묘지 입력

| 단계 | 사람                                         | 앱                                                                                                                                              |
| ---- | -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 위치 버튼(또는 단축키 M)                     | Earth를 묘지 주소 검색 상태로 연다. 묘지 코드를 클립보드에 넣고 화면 위에 "파일 이름에 Ctrl+V" 안내를 띄운다. 이 묘지를 "Earth 대기"로 등록한다 |
| 2    | Earth에서 경계를 그린다                      | —                                                                                                                                               |
| 3    | 파일(프로젝트) 이름에 Ctrl+V                 | —                                                                                                                                               |
| 4    | KML로 내보내기(어느 폴더든 기본 위치 그대로) | 내려받기 폴더·Google Earth 폴더를 살피다 새 KML을 찾는다                                                                                        |
| 5    | (선택) 위치 이미지 저장 — 7장                | 같은 코드의 이미지 파일이나 붙여넣은 캡처를 함께 받는다                                                                                         |
| 6    | —                                            | 코드(또는 단일 대기 묘지)로 묘지를 정하고, 다각형·면적을 검사한 뒤 앱 창을 앞으로 가져와 결과 패널을 띄운다                                     |
| 7    | 결과 패널에서 **저장**(Enter)                | 경계·면적·평수·원본 KML·이미지를 저장하고, 사용자 폴더의 원본을 앱 보관 폴더로 옮긴다                                                           |

결과 패널에는 고객명·묘지 주소·경계 미리보기(KML 좌표로 그린 선)·면적·평수·기존 평수와의 차이가 나온다. 저장 버튼에 초점이 가 있어 Enter 한 번이면 된다.

**코드로 연결된 경우 자동 저장을 선택할 수 있다.** 설정에서 켜면 6단계 뒤 바로 저장하고 "저장했습니다 · 되돌리기"를 10초 동안 보여 준다. 코드 없이 단일 대기로 연결된 경우에는 항상 결과 패널에서 저장을 누른다.

### 4.2 상황별 시작점

| 상황              | 시작점                                                                                 | 저장 시점                                                                           |
| ----------------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 영업 통화 중·직후 | 영업 카드의 **위치** 버튼                                                              | 결과 패널에서 저장. 통화 결과 저장·영업 배정과는 별개                               |
| 신규 등록         | 주소 입력 후 등록 폼의 **위치** 버튼. 누르는 순간 새 묘지 번호를 예약해 그 코드를 쓴다 | KML이 들어오면 폼의 경계·면적·평수 칸을 채우고, **등록**을 누를 때 고객과 함께 저장 |
| 기존 고객 일괄    | 5장 위치 입력 작업함                                                                   | 저장하면 다음 묘지의 Earth를 자동으로 연다                                          |

### 4.3 예외

| 상황                                               | 처리                                                                                              |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 코드 없는 KML + 대기 묘지 2개 이상                 | 자동 연결하지 않는다. "어느 묘지인지 모르는 KML 1개" 알림 → 누르면 대기 중인 묘지 목록에서 고른다 |
| 코드 없는 KML + 대기 묘지 없음                     | 연결하지 않고 알림만 띄운다                                                                       |
| 코드가 가리키는 묘지가 삭제됨                      | 적용하지 않고 알린다                                                                              |
| 같은 묘지에 두 번째 파일                           | 새 파일로 결과 패널을 다시 띄운다. 저장하면 교체(이전 버전 퇴역)                                  |
| 지점만 있는 파일, 도형 여러 개                     | 받지 않고 "경계(다각형) 하나로 다시 저장해 주세요"                                                |
| 경계 좌표가 다른 묘지·다른 등록 요청과 완전히 같음 | 저장을 막고 그 묘지를 알려 준다(아래 같은 경계 차단)                                              |
| "Earth 대기"가 2시간 동안 결과 없음                | 대기를 풀고 다음 열 때 다시 등록                                                                  |

- **같은 경계 차단(2026-10-22 사용자 결정)**: 들어온 경계가 다른 묘지의 현재 경계, 또는 처리 중인 다른 등록 요청의 경계와 **좌표가 완전히 같으면 저장·검토 요청·승인을 모두 막는다.** 예: Earth에서 328번 경계를 띄운 채 그대로 이름만 412로 바꿔 내보낸 경우. 이때 파일 이름·안의 이름이 달라 파일 지문(SHA-256)은 다르므로, 비교는 **경계 좌표**로 한다(좌표를 같은 자릿수로 반올림하고 시작점·방향을 맞춘 뒤 비교). 안내: "이 경계는 328번 묘지와 똑같습니다. 412번 묘지 경계를 새로 그려 주세요." 새로 그린 경계는 점이 조금씩 달라 해당되지 않는다. 영구삭제된 묘지·반려된 요청은 비교 대상에서 뺀다.
- 대기 목록은 PC·로그인 계정별이다. 다른 PC에서 내려받은 파일과 섞이지 않는다.
- 내려받기 폴더 감시는 `.kml`·`.kmz`(그리고 7장의 이미지 파일)만 보며, 설정에서 끌 수 있다.

### 4.4 저장된 위치 확인·수정

이미 저장된 경계를 마스터가 확인하고 고칠 수 있게 한다(2026-10-22 사용자 요청).

- **확인**: 고객 상세의 위치 칸에 저장된 경계를 위성지도 위에 그려 보여 준다(볼 때마다 실시간으로 그림, 저장하지 않음). 면적·평수, 저장한 사람·시각, 스크린샷도 함께 보여 준다.
- **Google Earth로 열어 보기·고치기**: **구글 어스로 열기**를 누르면 앱이 저장된 경계로 KML 파일을 만들어 연다. 이 파일의 이름과 경계 이름에는 이미 묘지 코드(`데모-328-K`)가 들어 있다.
  - Earth Pro는 파일을 바로 연다. Earth 웹은 프로젝트의 **KML 파일 가져오기**로 연다(앱이 파일을 내려받기 폴더에 두고 안내).
  - Earth에서 꼭짓점을 옮겨 고친 뒤 다시 내보내면, 코드가 이미 들어 있으므로 Ctrl+V 없이 앱이 같은 묘지의 결과 화면을 띄운다. 저장하면 새 버전으로 교체된다.
- **권한**: 수정 저장은 고객 정보 수정 권한(마스터·부마스터)이 한다.
- **위치 수정 메모(2026-10-22 사용자 결정)**: 관리자가 영업 통화 중에 위치가 이상하다는 것을 알게 되면, 고객 상세의 위치 칸에서 **위치 수정 메모**를 남긴다(예: "고객 말로는 소나무 왼쪽 두 번째 봉분"). 관리자는 위치를 직접 고치지 않는다.
  - 마스터·부마스터 메뉴에 **위치 수정 요청 N건**이 보인다. 목록에서 고르면 메모와 저장된 경계가 함께 나오고, **구글 어스로 열기**로 바로 고친다.
  - 새 위치를 저장하면 그 묘지의 메모는 자동으로 "처리 완료"가 된다. 고칠 필요가 없으면 **수정 불필요**로 닫는다. 메모를 남긴 관리자는 처리 결과를 볼 수 있다.
  - 메모는 묘지마다 열린 것 하나만 둔다. 이미 열린 메모가 있으면 내용을 덧붙인다.
  - 메모는 고객 자료이므로 고객 영구삭제 때 함께 지운다.

## 5. 기존 고객 일괄 입력 — 위치 입력 작업함

- 목록: 경계가 없는 묘지(지점만 있거나 없음). 사업 지역 → 시·군 → 주소순, 지역 필터, 진행률(예: 128 / 327).
- **시작**을 누르면 첫 묘지의 Earth가 열리고 코드가 복사된다. 4.1의 2~7단계를 하면 저장과 동시에 **다음 묘지의 Earth가 열리고 다음 코드가 복사된다.** 사람은 "그리기 → Ctrl+V → 내보내기 → Enter"만 반복한다.
- 찾지 못한 묘지:
  - **건너뛰기**: 목록 끝으로.
  - **현장 확인 필요**: 기존 현장 GPS 위치 요청으로 넘긴다. 승인된 GPS 좌표가 생기면 다음에 Earth를 그 좌표로 연다(주소 대신 좌표 검색).
- 여러 사람이 함께 할 때: 화면에 띄운 묘지를 짧게 점유한다(영업 배정과 같은 방식). 다른 사람에게는 "입력 중"으로 보이고 건너뛴다. 저장은 고객 버전 검사를 거친다.

## 7. 위치 이미지

### 남기는 방법 (사람의 추가 손: 한 번)

- **Earth Pro**: 파일 → 저장 → 이미지 저장. 파일 이름에 Ctrl+V로 같은 코드를 넣으면 앱이 KML과 같은 묘지로 받는다.
- 이미지 파일을 어느 프로그램으로 만들었든 이름에 같은 코드가 있으면(예: `데모-328-K.png`) 내려받기·Google Earth 폴더에서 KML과 함께 자동으로 가져간다.
- **Earth 웹**: Windows는 Win+Shift+S, Mac은 Cmd+Shift+4로 경계가 보이게 화면을 캡처한다. 앱 결과 패널이 뜨면 Ctrl+V로 붙여넣는다. 앱은 붙여넣은 이미지를 받아 저장한다.
- 이미지는 선택이다. 없어도 위치는 저장된다.

### 저장

- 한 묘지의 KML·스크린샷은 항상 같은 **묘지 폴더**의 같은 버전 칸에 함께 둔다: R2·NAS 모두 `{workspaceId}/묘지/{사업지역}/{시군}/{묘지번호}/위치/{저장일}_{버전ID}/`에 `original.kml`, `earth.jpg`(스크린샷), `manifest.json`. 그 묘지의 작업 사진은 같은 묘지 폴더의 `작업사진/`에 모인다(R2 설계 4장).
- 위치 이미지는 긴 변 1600px 이하 JPEG로 줄이되, **출처 표시(Google·영상 제공사)가 보이는 부분을 자르지 않는다.** 붙여넣은 캡처에 출처 표시가 없으면 "출처 표시가 보이게 다시 캡처해 주세요"라고 안내한다(자동 판별이 어려우면 안내 문구만 표시).
- **스크린샷은 그 묘지를 볼 수 있는 모든 역할이 본다**(2026-10-22 사용자 결정): 마스터·사장님, 부마스터, 관리자, 일반 작업자(배정된 묘지의 휴대폰 화면). 영업은 기존 고객을 볼 수 없으므로 자기가 작성 중인 등록의 스크린샷만 본다. 사내 화면에서만 쓰고, 고객에게 보내는 문자·외부 자료·광고에는 쓰지 않는다. 출처 표시는 휴대폰에서도 잘리지 않게 보여 준다.
- 위치 버전과 함께 퇴역·삭제되고, NAS 백업에서 1년 보관된다.

### 약관 관련 판단 (2026-10-22 확인)

- Google의 지도·Earth 이용 지침은 회사 보고서·제안서·발표 자료 같은 **업무 문서**에 출처를 표시해 쓰는 것을 허용 사례로 든다. 출처 표시는 어떤 경우에도 필수이며 지우거나 잘라서는 안 된다. Earth 콘텐츠는 상업·홍보 목적에 쓸 수 없다.
- 사내 업무 기록으로 보관하는 경우를 직접 언급한 문장은 없다. Google도 개별 이용이 허용되는지는 판단해 주지 않는다고 밝힌다.
- Google 지도 API(Maps Platform)로 받은 지도 화면은 사전 저장·캐시·보관이 원칙적으로 제한되므로, 앱이 지도 API 화면을 자동 캡처해 보관하지 않는다.
- 따라서 이 설계는 "사람이 Earth에서 출처 표시와 함께 만든 이미지를 사내 업무 기록으로만 보관"으로 범위를 좁힌다. 법적 확실성이 필요하면 별도로 법률 자문을 받는다.

| ---------------------------------------------- | ----------------------------------------- |

| 검토 요청의 위치 확인·승인                     | 마스터·사장님, 부마스터 (반려는 마스터만) |

- 영업은 묘지 번호 예약과 자기 요청 업로드만 할 수 있고, 저장된 원본·다른 묘지 위치는 열 수 없다. 서버에 영업 전용의 좁은 예약·업로드 기능을 둔다(현재 번호 발급은 마스터 전용 `lock_actor` 뒤에 있음).
- 스크린샷·경계 보기: 그 묘지를 볼 수 있는 모든 역할. KML 원본 파일 열기(Earth로 열어 수정)는 수정 권한이 있는 마스터·사장님·부마스터만. 현재 `earth-assets`의 사장님·마스터 제한을 이 기준으로 바꾼다.

## 10. 구현 순서

1. **묘지 코드·대기 목록·두 폴더 감시·결과 패널**: 기존 "가장 최근 파일 자동 적용"을 대체한다. 다각형 필수, 같은 경계 좌표 중복 차단.
2. **위치 입력 작업함**: 저장 후 다음 묘지 Earth 자동 열기, 점유.
3. **영업 카드·신규 등록 위치 버튼**: 신규 묘지 번호 예약과 등록 시 저장.
4. **위치 이미지**: Earth Pro 이미지 파일 인식, 캡처 붙여넣기.
5. **사본 정리 단순화**: 사용자 폴더 → 앱 보관 이동, `.earth-files` 제거, 문서(`usage.md`, `data.md`, `maps.md`) 갱신.

## 12. 검증 기준

가짜 회사·가짜 고객으로 확인한다.

1. 코드가 든 KML은 다른 고객 창이 열려 있어도 그 묘지에만 들어간다.
2. 대기 묘지가 둘 이상일 때 코드 없는 KML은 자동 연결되지 않는다.
3. 작업함에서 저장하면 다음 묘지의 Earth가 열리고 다음 코드가 클립보드에 들어간다.
4. 신규 등록에서 예약 번호 코드의 KML이 폼에만 채워지고, 검토 요청 → 승인 후에만 그 번호의 묘지 폴더로 옮겨져 DB에 저장된다. 작성 중 취소·24시간 만료·반려 시 사용자 폴더·앱·R2의 해당 파일이 모두 지워지고 NAS 백업에도 남지 않는다.
5. 지점 파일·도형 여러 개는 거부된다.
6. 저장 후 내려받기·Google Earth 폴더에 원본이 남지 않는다.
7. 위치 이미지가 없어도 위치는 저장된다. 이미지가 있으면 같은 버전으로 묶인다.
8. 교체·영구삭제 때 원본·이미지가 함께 정리되고, 같은 이름·주소의 다른 고객 자료는 남는다.
9. 영업 통화 중 위치 저장이 통화 결과·배정 상태를 바꾸지 않는다.
10. 328번 경계를 띄운 채 이름만 412로 바꿔 내보낸 KML은 저장·검토 요청·승인이 모두 막힌다.
11. 관리자의 위치 수정 메모가 마스터·부마스터 목록에 나타나고, 새 위치를 저장하면 자동으로 처리 완료된다.
12. 부마스터 계정에는 반려 버튼이 없고, 서버도 부마스터의 반려 요청을 거부한다.

## 13. 남은 확인 사항

- Earth Pro를 함께 쓸지(과거 사진·이미지 저장이 필요하면 권장).
- 코드 연결 시 자동 저장을 기본으로 켤지.
