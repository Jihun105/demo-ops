# 전체 진행 순서 (권한 · R2 · KML · 청구·입금 · 휴대폰)

상태: 2026-10-22 사용자 요청으로 작성한 제안. 각 단계는 시작 전에 계획을 설명하고 사용자 승인을 받은 뒤 구현한다.

2026-10-22 사용자 결정: **1단계(NAS 백업)는 전면 보류.** 0단계 → 2단계부터 하나씩 진행한다.

관련 설계: [권한](2026-10-22-role-permissions-design.md), [R2 보관·삭제](2026-10-22-r2-storage-lifecycle-design.md), [KML 위치](2026-10-22-kml-location-design.md), [영구삭제](2026-10-20-customer-permanent-purge-design.md). 청구·입금과 휴대폰은 아직 설계 전이다.

## 순서를 정한 기준

1. **되돌릴 수단부터.** 큰 서버 변경 전에 회사 백업이 있어야 실수해도 복구할 수 있다. R2 자동 삭제도 백업이 있어야 켤 수 있다.
2. **바닥부터.** 모든 새 기능이 "누가 할 수 있나"를 묻는다. 권한 판정 함수가 먼저 있어야 이후 기능을 한 번에 맞게 만든다.
3. **얽힌 것은 한 번에.** 영업 등록 검토 요청함·묘지 번호 예약·KML 새 흐름·R2 검토 대기 칸은 서로 맞물리므로 같은 단계에서 만든다.
4. **현장 검증은 마지막에.** 중간에 검증하면 뒤 단계에서 다시 해야 한다.

- 각 단계는 실시간 개발 화면(`npm run dev:live`, 이 맥의 개발 전용 서버 `demo-dev-live`)에서 PC 앱 창과 Chrome 휴대폰 화면(`127.0.0.1:56331`)으로 역할별 계정을 직접 눌러 확인한다. 운영 서버·운영 자료는 쓰지 않는다.
- 2단계에서 배정 없는 사진 보고를 없애면서 휴대폰의 단독 "작업 보고" 화면은 닫았다(주소는 작업 확인의 보고 목록으로 연결). 그 화면이 쓰던 위치 검색 코드(`mobile/src/work-reports.js`)는 더 이상 쓰이지 않으며 7단계에서 정리한다.
- 5단계는 사람이 하는 입력 작업이라 6·7단계 개발과 동시에 진행할 수 있다.
- 6단계(청구·입금)와 7단계(휴대폰)는 서로 독립적이어서 순서를 바꿔도 된다. 현장에서 휴대폰을 먼저 쓰기 시작해야 하면 7단계를 앞당긴다.
- 0단계에는 커밋하지 않은 기존 변경(195개, 2026-10-22 확인)을 내용별로 나눠 커밋하는 일을 포함한다. 권한 작업의 기준점을 만들기 위해서다.
