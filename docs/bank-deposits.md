# 입금 문자 자동 처리

## 사용

은행 문자가 오는 **갤럭시 한 대**에 최신 정식 APK를 설치한다. 사장님/마스터로 로그인한 후 **설정 → 입금 문자 자동 처리 → 이 휴대폰에서 수신**을 누르고 문자 수신 권한을 허용한다. 기존 수신 기기가 있으면 변경 확인을 받는다. 다른 기기에 전송 대기 문자가 남았다면 먼저 처리한다.

농협 `1588-2100`, 등록된 회사 계좌의 입금 문자만 대상으로 한다. 잔액과 다른 문자는 전송하지 않는다. 문자 수신 시 앱 전용 보관함에 기록하고, 인터넷 연결 후 서버로 보낸다. 앱 화면을 열어둘 필요는 없다. 설정의 전송 대기 건수로 아직 서버에 도착하지 않은 문자를 확인한다.

서버에서 다음 조건이 모두 맞을 때만 입금을 자동 확인한다(2026-10-27판, 새 청구서 기준).

- 청구 문자를 보낸, 아직 입금되지 않은 청구서(한 묘지에 한 해 하나)이며 청구서·묘지·고객이 삭제·숨김 상태가 아니다.
- 입금자명이 지금 고객 이름과 정확히 같고, 입금액이 청구서 금액(보낸 금액)과 같다.
- 청구 문자를 입금 시각보다 먼저 보냈다.
- 위 조건에 맞는 청구서가 한 장뿐이다. 따로 기억한 다른 입금자명으로는 자동 확인하지 않는다.
- 입금 시각이 휴대폰 수신 시각 기준 15분 이내이고 같은 분·이름·금액의 입금이 이미 접수되지 않았다.

자동 확인된 청구서는 입금 대기에서 **최종 문자**로 넘어간다(휴대폰은 청구 신호로 바로 갱신). 그 밖의 입금은 PC **청구·입금 → 확인 대기**에서
후보(이름·금액, 기억한 입금자명, 이름만, 금액만)나 **진행 작업에서 찾기**로 청구서를 골라 확인하거나 빼 둔다. 여러 묘지를 한 번에 입금한
경우 여러 청구서를 함께 고를 수 있다. 입금을 취소하면 그 입금 문자는 확인 대기로 돌아간다. 휴대폰 확인 대기 목록은 없다.

감사 문자(최종 문자)는 자동으로 보내지 않는다. 사장님·마스터·부마스터가 휴대폰 **청구 → 최종 문자**에서 보낸다.

## 동작 범위

- Android 강제 종료, 전원 꺼짐, 문자 권한 해제 상태에서는 수신하지 못한다. 다시 앱을 연다고 이전 문자함 전체를 읽지는 않는다.
- 절전·통신 불량으로 서버 전송이 늦어질 수 있다. WorkManager가 네트워크 연결 후 재시도한다. 기기 제조사별 실제 수신/절전 테스트가 필요하다.
- SMS 권한은 Android 설치 경로/정책에 따라 제한될 수 있다. APK 설치 후 실제 갤럭시의 수신 권한과 잠금 화면 수신을 확인해야 한다.
- 로그아웃하면 이 기기의 수신이 중단된다. 이미 보관된 전송 대기 문자는 보존하고, 같은 회사로 수신을 다시 켜면 이어서 전송한다.
- 서버가 이 휴대폰을 거부해도(401·403: 함수 배포 설정 오류, 수신을 켠 마스터 계정 사용 중지, 다른 휴대폰으로 변경 등) 수신은 끄지 않는다. 문자는 계속 보관하고, 설정에 "서버 연결 끊김 · 전송 대기 N건"과 **다시 연결** 버튼을 보인다. 새 문자가 올 때마다, 그리고 설정을 열 때마다 한 번씩 다시 보내 보며, 다시 연결하면 보관한 문자부터 보낸다. 보내지 못한 채 30일이 지난 문자는 새 문자가 들어올 때 정리한다. 수신은 **수신 중단**이나 로그아웃으로만 꺼진다.
- 보류 검토는 PC 청구·입금 화면에서 한다. 은행 문자 수신은 갤럭시가 담당한다.
- SMS 발신 번호는 은행 API 서명/실제 계좌 거래 조회를 대신하지 않는다. 원본 거래번호가 없으므로 모든 재발송/수동 중복 기록을 완벽하게 구분할 수는 없다.
- 감사 문자 자동 발송은 포함하지 않는다.

## 서버 적용과 구조

`database/cloud/bank-deposits.sql`을 기존 자동 공유 SQL 이후 적용한다. 생성하는 테이블은 `demo_bank_devices`(수신 기기 토큰 해시), `demo_bank_receipts`(입금 접수/검토 내역)다. 일반 작업자·영업은 금융 자료에 접근할 수 없다. 관리자·부마스터는 데스크톱에서 보류 입금을 확정·제외할 수 있고, 수신 기기 등록은 휴대폰을 쓰는 사장님·마스터가 한다.

최종 확인 문자 기능은 다른 기존 SQL을 적용한 뒤 **`database/cloud/completion-messages.sql` 전체를 마지막으로 실행**한다. 청구 발송과 최종 확인 문자 이벤트를 구분하도록 검증을 확장하며 기존 고객·청구·입금 자료, RLS와 자동 공유 트리거는 유지한다. 이 기능에는 Edge Function 재배포가 필요 없고 최신 앱 업데이트가 필요하다. 실제 서버 적용·기기 설치 여부는 작업 완료 안내를 확인한다.

`node scripts/build-server-function.cjs`로 생성한 `artifacts/server/bank-deposits/index.ts`를 Edge Function **bank-deposits**로 배포한다. Supabase의 JWT 사전 검증은 끈다. 함수 내부에서 기기 토큰 또는 사용자 로그인을 검증한다. 새 유료 서버나 저장소는 필요 없으며, 함수 호출과 DB는 기존 플랜 사용량에 포함된다.

- `src/shared/bank-deposits.cjs`: 은행 문자 분석·후보 판정. Supabase 의존성 없음.
- `src/server/bank-deposits-handler.mjs`: HTTP 입력·권한 검사와 최소 응답. 인증 조회와 저장소를 주입하므로 다른 서버에서도 같은 처리기를 사용한다.
- `src/server/bank-deposit-service.cjs`: 판정/재시도/수동 검토. 저장소는 `context`/`commit` 계약으로 주입한다.
- `supabase/functions/bank-deposits/index.ts`: 인증과 PostgreSQL RPC 어댑터.
- `mobile/src/bank-deposit-api.js`: 화면의 공급자별 연결부.
- Android `BankSmsReceiver`/`BankInboxStore`/`BankInboxWorker`: 수신, 영속 큐, HTTPS 재시도. 사용자 로그인 토큰 대신 접수 전용 토큰을 AndroidKeyStore로 암호화한다.

서버는 청구서를 잠그고 다시 확인한 뒤 입금과 접수 상태를 한 트랜잭션으로 반영한다(`database/cloud/desktop/bank-claims.sql`). 그 사이 청구서가 바뀌었으면 확인 대기로 둔다. 접수 식별자는 문자 PDU에서 만들고 재시도에서도 유지한다. 보류 갱신도 기존 billing 변경 신호로 전달하며 주기적인 서버 조회는 추가하지 않는다.

서버 공통 처리기 분리와 SDK 버전 고정(`2.116.0`)을 운영에 반영하려면 `bank-deposits`, `staff-accounts`, `work-reports` 함수를 다시 배포한다. 이 구조 변경에는 SQL 재실행이나 저장된 자료 변환이 필요 없다. 기존 운영 함수는 배포 전까지 그대로 동작하며 로컬 빌드가 운영 배포를 대신하지 않는다. 같은 빌드 스크립트에 `staff-accounts` 또는 `work-reports`를 전달하면 각 함수의 대시보드용 단일 파일을 생성한다.

## 다른 서버로 이전

이번 분석·판정 코드와 Android HTTPS 전송은 재사용할 수 있다. PostgreSQL 테이블/처리 함수도 이전할 수 있지만 Supabase 전용 `auth.users`, `auth.uid()`, RLS 권한 함수와 변경 신호 연결은 새 인증/알림 방식에 맞춰 바꿔야 한다.

**앱 전체가 서버 주소만 바꾸면 이전되는 상태는 아니다.** 기존 로그인/직원 계정 발급, 동기화 RPC/RLS, Realtime, 사진 업로드 함수가 Supabase API를 직접 사용한다. 기존 `syncRecords(transport)` 같은 경계는 재사용하고, 실제 이전 때 공급자 어댑터를 교체해야 한다. 고객·청구·입금 데이터는 PostgreSQL, 사진은 S3 호환 R2라 데이터 형식 자체가 잠긴 구조는 아니다. 지금 모든 기능을 미리 범용 서버 프레임워크로 바꾸지는 않는다.

## 검증

Node 테스트는 분석/유일 후보/중복/시각/부분 입금, 실제 PostgreSQL(PGlite) 권한·중복·순번 충돌·신호, 화면의 검토/오류 유지 동작을 검증한다. Android 단위 테스트는 타 문자 무시·잔액 제거·수신 식별자·영속 큐를 검증한다. 이 테스트와 실제 통신사 SMS/갤럭시 절전 상태에서의 수신 검증은 별개다.

2026-10-11: 운영 SQL과 `bank-deposits` 함수 배포 완료. 실제 엔드포인트에서 인증 누락 401, 미등록 기기 403 거부 확인. 수신 기기 등록과 실제 갤럭시 문자 수신 시험은 아직 진행하지 않았다.

2026-10-17: 올해 진행 작업 제한과 확인 대기 흐름을 소스에 반영했다. 기존 SQL 테이블·동결 릴리스는 변경하지 않는다. 운영 반영에는 `bank-deposits` 함수 재배포와 최신 PC·휴대폰 앱 업데이트가 필요하다. 소스 수정·로컬 빌드가 실제 배포·설치 완료를 뜻하지 않는다. 기존 확정 입금과 과거 회계 기록은 유지한다.
